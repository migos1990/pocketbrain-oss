# The owner's home: one box, a diary, prose pages

The owner's phone UI (owner's direction, 2026-10-26, and the owner app brief of 2026-10-30) is four tabs, On your mind, Memory, Ask and Who knows, plus a page that opens on prose with references and a settle screen, the only place that ever asks. On your mind is the home: one text box and a diary of what the brain learned. This page describes what is built today.

## The diary

Every fact change that `write()` commits, and every answer to a conflict (`settle()` in `src/core.ts`), adds one row to `diary/YYYY-MM.jsonl` in the brain, in the same commit as the change (`src/diary.ts`). The owner's home reads these rows, never `git log`.

A row holds: `at`, `fact_key`, the page `title`, `kind` (`new`, `changed`, `retracted`, `item_added`, `conflict`, `settled` with `settles` naming the conflict, or `confirmed` when the hub filed a value the page already held, with `added` naming the sources it added; its Undo takes them out), `from` and `to` (the value before and after; left out for a new fact's `from`), `source_word` (where it came from: `you`, `email`, `calendar`, `notion`, `assistant`, or the source's scheme), `by` (the writer) and `accepted_by` when someone else saved it, `confidence` (`stated` or `inferred`), `rank` (the source's place in the conflict order, so the home can show the least certain lines first), `sources` (how many), `sensitivity`, and `undo_token`.

Fact changes that came without a row of their own (the hub's filing, upkeep, merges, hand edits, and everything from before the diary existed) are caught up by the hub's minute tick (`catchUpDiary` in `src/diary-catchup.ts`). New commits are read oldest first from where the last run stopped; the first 7 days are read newest first, so the home fills from today backwards. One git call lists the commits with their files, and a run compares at most 1500 note versions. A commit that already touched `diary/` is skipped, as is the brain's first commit. Each fact whose shown value changed becomes one row at the commit's time, by the record's writer, with `commit` naming the commit. Rows are read in time order, so a caught-up row sits where it happened. The cursor is hub state in `.git/pb-diary-cursor`. `pocketbrain diary catchup --dry-run` prints what a run would read and add (counts only, nothing written).

What adds no row:

- a write that changes no value (the same value again, sources merged), a refused write, and anything waiting in the inbox;
- the hub's own commits (page text, name keys, re-ranks, backups), which don't go through `write()`.

A secret row would carry no value, though secrets are never stored in v1 anyway.

`diary/` is not a content folder: no carve, cell or assistant view reads it, and an assistant's write there is refused (`protected_paths` in `src/checks.ts`).

## Undo

Every diary line that was a write can be undone (`undoFact(root, undo_token)` in `src/undo.ts`). Undo is a forward write by the owner, never `git revert`, so it still works after the night's page text or any later commit touched the same file:

- a changed value: the record it replaced comes back from history exactly as it was (value, date, sources, verification), and the undone record goes to history marked never right (`ended_by: { by: owner, correction: true }`);
- a new fact: it is taken out, into history the same way;
- an added list item: it is ended the same way;
- a taken-back fact: the record comes back.

Because the undone record keeps its value, date and sources, the same value from the same source is a repeat the write path ignores, so a mail read again tomorrow doesn't put it back. A different source saying the same thing is new evidence and is weighed as usual.

When the fact has changed since the line (another value, a conflict, the page gone), nothing is undone and the answer is `changed_since`, which the home shows as "Changed since". A line already undone, or a conflict line (settled on the settle screen instead), undoes nothing. Undo on a `settled` line opens the conflict again: the fact, its history and the conflict go back to how they stood just before the answer (read from the answer's own commit), while the answer is still the live value. The undo is a diary line of its own, `kind: undone`, with `undoes` naming the line it undid. After the undo the page writer rewrites the page's text from its facts, in its own commit. When the undone fact was the last one on a page whose every fact the owner has undone, with no words but the hub's and nothing linking to it (a page just started from the box), the page goes in the same commit.

## A page follows the workplace you name

When your own word says where someone works (the box, a page's box, the editor's set-fact, or a value you type on Settle) and their page sits in the area of the org it named before, or named none, the page moves to the new org page's area (`followArea` in `src/area-follow.ts`, G664). That fixes a page an import filed under the wrong org. The move is one owner commit naming the commit that set the workplace (`Area-Follows: <sha>`) and a diary line, `kind: moved`, which the home says as "Maya Chen's page moved from Work to Personal, with the workplace you named." Its Undo puts the old area back, and answers "Changed since" when the page moved again or is gone (merged or forgotten).

Nothing else moves a page: a workplace from a source or an assistant, a tap on a source's side on Settle, filing and upkeep all leave the area alone, and so does an org page in the same area, or a page you placed in another area than its org's. A workplace with no org page changes the fact and leaves the page where it is. When two org pages carry the name you said (an import's two-name page, such as "Northwind / Brightwell", beside "Brightwell"), the page never picks one: it stays, and once only one is left, saying the workplace again (or setting it in the editor) moves it from the org it had before. A move never hands the page to someone else's assistant: when a collaborator you shared a slice with (docs/share.md) or a co-owner's assistant (docs/household.md) would see the page in the new area and doesn't now, it stays where it is, since sharing with a person is its own step. The new org page's area must also be one you or the hub set, never one an assistant's write chose, even when you accepted that assistant's new org page or the hub filed it. Only `area:` changes: how private the page is, who it is shared with and who it is hidden from stay as they were. Which assistants read the page follows from the new area as it would after a move by hand.

## The text box

What the owner types or dictates goes to `ownerSayModel(root, text, { page }, model)` in `src/owner-say.ts` (owner, 2026-10-29).

**The model's reading.** When a model is set up for the step `say.read` (it runs on the cheap model, Haiku on Anthropic, like the other executor steps; `rules/models.yaml` can move it; `pocketbrain models` lists it), one short call per sentence asks it what the sentence means: a question (which page, which attribute), facts (name, attribute, value, time words), a request to act, or unclear. It sees the sentence and the attribute names the box may write (the brain's own from `rules/checks.yaml` plus role, org, last_contact, next_step, city, birthday, emails, phones), never a page, a title or a fact. Code then checks every part (`checkReading`): each name and value is made only of words the owner typed, the attribute is on that list (a secret one goes on to be refused with its reason), the time words are in the sentence. A value that reports what someone else does or wants ("wants the slides by Thursday", "moved to Friday") is dropped too, except a role ("runs the new lab"): it is never the owner's next step. A fact that fails is dropped; a reading with nothing left, a failed or slow call (8 seconds), or no key for the provider means the fixed patterns below read the sentence instead, as they do with no model at all. Forget, send, a tapped chip, and a sentence holding a secret's shape or a secret attribute's name are never sent to the model. The reading goes on through the same steps as the patterns' (names, write, reply), so nothing the model says writes by itself, and every write is still the owner's word through `write()`. Each call is metered and capped like every model step and logged in `log/judgments.jsonl` (the sentence as a hash). `bun evals/run.ts --llm --only say` runs ten everyday sentences through it.

1. **Intent.** `forget …`, `erase …`, `hide …`, `don't trust …` is a forget; `send …`, `reply …`, `book …`, `tell <name> to …` is an act; a question mark or a question word at the start is a lookup; anything else is something the owner is telling the brain.
2. **Patterns.** `<name> moved to / works at / joined / is now at <value>` (org), `<name>'s <attribute> is <value>` (also `her <attribute> is <value>`), `<project>: next step is <value>`, `met / saw / called / spoke with / had coffee (lunch, a call…) with <name> <when>` (last_contact), `<name> runs / leads / heads / manages / teaches … <x>` (role, in those words), `remind me to <x>` (a next step on the page `<x>` names, else the page the owner is on; "tomorrow" keeps its date). `I owe / promised <x>` and `I need to / have to / must / should / am going to <x>` are the owner's own next step, in their words, on the page of the person `<x>` names, found the same way ("I owe Ben the sample by tomorrow" is a next step on Ben's page, "by 9 Oct 2026"; G557); one that names nobody the brain holds writes nothing. `<name> is a / an / the <value>` is a role; `<name> is <value>` with no article is only a guess at a role: nothing is written, the box asks "Did you mean to note a role?" and its chip says it plainly (`<name>'s role is <value>`). A negation ("not dean", "isn't dean", "no longer dean") keeps nothing and says so. A sentence with commas or "and" is read clause by clause and every clause that parses is kept; a pronoun means the first clause's name, or the page the owner is on. A date right after "is" is the value ("her birthday is 12 March"), not when it was said.
3. **Dates.** Only a date the owner said: `today`, `yesterday`, `on 12 Oct`, `2026-10-12`; `this week`, `last week` and `last month` are stored as approximate and the reply says it guessed. With no date, the fact holds as of the day it was said.
4. **Names.** A name that fits one page (title, alias, or a first name one person has) is that page. A near miss asks "Did you mean …?" with the pages as chips; a chip sends your own sentence again with that page's name in place of the one you typed, nothing else. A tap is recorded as `owner:<day>/home/chip`, and only a chip the box offered this sign-in counts as one; anything else posted as a chip is read as typed words. A name no page has starts a page (below).
5. **Write.** The value goes through `write()` with `owner: true` (agent `owner`, in-process only, refused for anyone else): it is saved as the owner's own word (`confirmed-by-owner`, source `owner:<day>/home`), through every write check, and ranks first in the conflict order. Attribute names that only hold secrets (password, PIN, card number and the like) are refused before any write. A fact with a conflict waiting, in disputes/ or in the inbox (`src/settle-inbox.ts`), is settled by the typed value instead of written over, and when a side of that conflict is private (the settle screen hides it on the 30-day sign-in) the box asks to sign in again first and writes nothing (G610, G646). The same goes for any value that would land private: a private page or fact, or another person's health, school, legal or money matter (which `write()` forces private) waits for a fresh sign-in (`say.private-signin`); a to-do that only sounds like money ("I owe Ben the sample") is still noted (G646).
6. **Reply.** One fixed sentence per outcome from `OWNER_SAY` in `src/owner-errors.ts`. "Noted:" means something was written and nothing disagreed, and says what in the same sentences the home uses for its memories (`LINE_COPY` in `src/dashboard/home.ts`): "Noted: Jane Roy is dean now.", "Noted: You need to send Jane Roy the syllabus by Friday." (a to-do the owner said as theirs, "I owe…", "I need to…", is said back with "You", on the home too; a reminder's "Next for Jane Roy: call her" keeps its form), "Noted: You were last in touch with Jane Roy on 8 Oct 2026.", never "Jane Roy: role is dean"; "Settled:" means a conflict was waiting on that fact and the owner's typed value answered it (`ownerDecide`, the same as typing it on the settle screen), so nothing asks about it any more; "That's different from what … had" means it opened a conflict with the page's value, both kept, and the choice waits on the home (the reply carries the diary line's Undo and says who sees it: "your assistants" or "only you"); any other reply means nothing was, and none opens with a stock phrase: "I already have that. Nothing changed.", "Nothing saved. …". A part of the sentence the box kept nothing from is named after the reply ("I left out “she wants the slides by Thursday”; say it on its own to keep it."), with the model or without, so one fact is never kept while another is dropped in silence. A question gets one sentence and no chip, and never writes: "what is Jane's phone" says that fact ("Jane Roy's phone is …"), or that the page doesn't hold it yet, or that two answers wait on the home; a question naming only a page says the page's opening prose (else up to three of its facts). A question may name any page the owner keeps (a bank, a decision), not just people, organisations and projects. A private, money, health or legal value, or one the owner hasn't seen yet, shows only after a fresh sign-in (below), as on a page. Act never writes: it says the assistants do that. Forget first says what it would remove; "yes, forget <name>" (its chip) then forgets, only after a fresh sign-in (below): a person with every trace (`src/forget.ts`, undo within 14 days), any other page in one owner commit that Bring back reverses. A name no page has starts its page at once with everything the sentence said (owner, 2026-10-29): a project for a next step, otherwise a person, in the area of another page the sentence names, else of the page the owner is on, else `personal`. The reply says where ("New page for Marco Bianchi in personal; Undo takes it back"), and its one Undo takes back everything the sentence noted, newest first, so the page goes too. The area decides which assistants see the page, so moving it is on the page's Who sees this. Only a brain with no `personal` area still asks where the page lives, with one chip per area (`new page in <area>: <sentence>`). What someone else said is theirs, not the owner's: "Paul told me Jane is the dean", "according to Paul, …", "I heard …", "apparently …", "per Paul, …", "via Paul, …", "as Paul put it, …", "Paul let me know …", "supposedly …", the same said after the fact ("…, Paul says", "…, says Paul", "… (per Paul)", "… according to Paul", G661), "in Paul's words, …" and in French ("selon Paul, …", "d'après Paul, …", "Paul m'a dit que …", "il paraît que …") note nothing (with the model or without, G556), and the reply says whose word it is, with one chip that says the fact alone as the owner's own for when they know it (`hearsay` in `src/owner-say.ts`, G528). What it knowingly misses (an adverb inside the clause, "Jane is apparently the dean") and the owner's own sentences it knowingly takes for hearsay ("Paul says hi to Jane") are rows in `test/ceilings.test.ts`, as are the write path's order guard outside a preference (`speaksToReader` in `src/checks.ts`). A near name still asks which page was meant; its chip says the owner's sentence again with that page's name. Every chip resends the owner's own sentence; the server knows it was a tap (`chip=1`) and records the owner ref as `owner:<day>/home/chip`, so a tap stays told apart from typed words.

`test/owner-copy.test.ts` is the copy contract: no owner-facing string of these screens may say proposal, dispute, slice, carve, verification, candidate, step, tier, inbox, deck, card, YAML or a file path.

## Older sources never re-ask

Once the owner has said a value in their own words, an assistant's or a source's different value dated a day or more before it is something the owner already corrected (`ownerDispute` in `src/write.ts`, spec §4.6). It goes to the fact's history as superseded (`ended_by.step: 6`; the same value again merges its sources there), opens no conflict, and adds a `kept` diary row. The home folds those to one line per fact per day: "3 older emails still say Jane Roy's role is Course coordinator; I kept your word". A source dated the same day or later still opens a conflict, since it may be newer than the owner's word. A source's fact from a capture or a pull takes the same path: the hub files it on its tick (`fileVerdict` in `src/filing.ts`, row "kept your word") instead of asking first.

Your own words never dispute each other (audit v5, midday: "chair last week" after "dean" opened a conflict with both sides "you said"). It's dean now; …"; nothing asks. Said the same day or later, the latest thing you said is your word now and replaces it, with the old one in history.

## A fresh sign-in

What can't be taken back, or shouldn't show on a borrowed phone, needs a sign-in from the last 10 minutes (`FRESH_MINUTES` in `src/dashboard/server.ts`). These are forgetting from the box, a private or held value on a page (Details shows "private · sign in again to see it", and a private page shows only its title), the kept words of a source item that a private, held, money, health or legal fact on that page cites (one mail can give several facts, so its words can carry that value even under an everyday sentence), Show on the home, and Let it through on a held message's settle screen. Every page other than the owner screens (the four tabs `/home`, `/memory`, `/ask` and `/who`, a mark's sheet `/let`, then `/p/<id>` and `/settle/<id>`) can show a private value, so Settings, the edit page `/note/<id>`, the brain search, Where from, history, the map and the rest open only within those 10 minutes too (audit v5). The buttons follow the same rule, checked once before any action runs (`STALE_OK` and `needsFresh` in `src/dashboard/server.ts`, G525): on the 30-day sign-in only what the owner screens offer to keep something back or put it right runs (settle a conflict whose sides the screen shows, keep a held message back, Undo a diary line, Fix everywhere, hide a page from an assistant); a pick or typed answer on a private conflict, whose sides show only after a fresh sign-in, needs one too (G553); a conflict counts as private when a side, the page or the live value is private now, or when its values or attribute are shaped like money, health or legal, as the home card withholds them (`settlePrivate` in `src/core.ts`, G583); every other button, an old form's `mail-release` included, answers **Sign in again** and changes nothing. Past that, the screen offers **Sign in again**. That button ends this browser's sign-in, so the next screen is the usual sign-in, and on the phone it sends a new link.

How private a line is comes from the page and the fact as they are now, never from the diary row written back then (`privateNow` in `src/dashboard/home.ts`, G551): a page or fact made private or secret after its value was filed shows "something new" on the home, in the page's Changed list, on Memory's changed pages and on the Let sheet, and on the 30-day sign-in the page's prose shows "(private)" where that value was, and an answer on Ask given on that sign-in hides once its page or fact is private. Ask and the box answer a page with that same text (`shutBody` in `src/dashboard/home.ts`), so a fact made private after it was written shows in none of them (G582). The page's text is checked for each such value twice: the exact words first, then the spellings an assistant's view also catches (spaced out, hyphen dropped, look-alike letters; `findCarried` in `src/match.ts`), where the whole line goes (G614).

Undo on a line about something you chose to see (Show) holds that value for you again: no assistant gets it until you Show it once more; it never removes the fact (`rehold` in `src/undo.ts`, G552). A line kind with nothing of its own to undo (an older source kept as history, a held or set-aside proposal) says so and changes nothing.

A private page open after a fresh sign-in says so in one quiet line: "Only you see this page. It stays open 10 minutes after you sign in."

No address holds a value or a file path. After a button (Show, Undo, Save) the dashboard goes back with only a short id in `?ok=` or `?err=`; the words wait on the hub for that sign-in (`keepFlash` in `src/dashboard/server.ts`), so a held value shown by Show never lands in the browser's history. An error from inside the code says only that something broke inside the dashboard (`ownerFacingError`); a refusal keeps its own words, with any path replaced by "a file".
