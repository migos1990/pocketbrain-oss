# One thing, one page (fold twins)

A writer that files a page into an area or level it can't see gets a new page every time it writes by that name: write() only matches a name against pages the writer can see, and a new page from a writer outside the wall gets a random suffix (`projects/garden-planning-ea6eea`), so the reply never says a hidden page exists (G28). One project then shows twice on Memory (owner's phone, 2026-11-03; G635).

The hub sees everything, so it folds such twins (`src/fold.ts`):

- **What folds.** Two active pages in the same folder with the same type, the same name (as `compareKey` reads it), the same area and the same level, of a kind where a name names one thing: projects and organisations. People have their own proposal (docs/same-person.md). Decisions, money, events and notes never fold: two decisions or bills with one name can be two things, and two write-ups of one meeting each keep their prose (upkeep's `possible-duplicate` line still lists them).
- **Which page stays.** The plain id first (it was there before any blind writer), then the one more pages link to (fewer links move, and the id your assistants know stays), then the one made first. The other becomes a `merged` pointer to it.
- **How.** `mergeNotes` with `reflect` as the author: no winner is picked, a fact the two pages disagree on becomes a conflict you settle, and a fold that would change what any assistant gets (`mergeBlocked`, `brainChanges`) is not done. An open conflict on either page holds the fold until you settle it, so one fact never waits twice.
- **When.** On by default (the owner's word, 2026-11-03). `pocketbrain fold off` (`fold: { twins: false }` in `rules/policy.yaml`) stops it, and then each upkeep run only counts what would fold (`twin-would-fold`, one line); `fold on` starts it again. While on, every upkeep run folds (step 1c2, before page text is written, so the kept page's opening is written once). A fold is an `auto-fix` finding on the page that stays, with the `pocketbrain fold undo <commit>` that puts it back. A held fold is one count-only `twin-held` line under a key that is no page's id: a fold is held when the two pages read differently for some assistant, and naming the page would tell an assistant that sees it that a page with its name exists out of its view.
- **The writer.** Nothing changes for it: the pages it wrote were outside its view before the fold and stay outside it after, and its next write by that name answers as before.
- **By hand.** `pocketbrain fold` is a dry run: what would fold, what is held and why (a pair held by an open conflict names that conflict, `settle disputes/<id> first`, and folds the night after it is settled), and how many new conflicts the folds would open. `pocketbrain fold --apply` folds them. `pocketbrain fold undo <commit>` puts one back, also after later writes (G644): the dropped page comes back as it was, a conflict the fold opened that nobody answered goes away, and on the kept page each part the fold changed goes back unless a later write changed it again, which stays; upkeep's link repoints and the page writer's text go back with it. It refuses, saying so, only when the dropped page itself changed since. Each fold and undo is a line in `log/folds.jsonl`.
- **On your mind.** A fold is one line, "Two pages called X are one page now", never a line per moved fact. Its Undo is the fold's: the same as `fold undo`, and once the fold is undone by either door the line says Undone. The diary catch-up writes the line from the fold's commit and makes no lines for an undo's commit.

A writer that keeps writing into an area it can't see makes a new twin with each write, and each folds the next night; the real fix is its grant or the area it writes, which the fold doesn't change.

The dropped page's own text stays in git and on its merged pointer; the kept page's text is written again from its facts that night.
