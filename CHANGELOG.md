# Changelog

Notable changes to pocketBrain. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow [Semantic Versioning](https://semver.org/). Before 1.0, a minor version can change the brain format or the agent door; each such change is listed under **Changed** with what to do.

## [Unreleased]

- Public repo prep: a short README for readers of the architecture (layers, how agents connect, walls, conflicts, the Gardener, what is not built), the full tour moved to docs/overview.md, CONTRIBUTING opens issues now and code once the contributor agreement is settled, and CLA.md stays out of the public export until then.

- Household brain: a co-owner (`co_owners` in policy.yaml) whose word counts like the owner's in named areas only; her assistant is held to those areas, personal at most, no money. An agent's retract of an owner's word now waits in the owner's inbox. Her word never touches a fact hidden from her assistant, and the owner confirming her value makes it his word. See docs/household.md.

### Security

- With cells on, as the hub serves, the gardener's `last_run` no longer returns its accepted values on facts the owner has since hidden from it, and its source rechecks no longer pick such facts: its tools now filter by the hub's own carve (G198).
- The sealed edge: queued writes are signed under a key only a live token or the hub's home state can derive, so whoever stores the bundles and the queue can't commit as an agent; bundles no longer name the token hashes `rules/tokens.yaml` stores; agents with hours (the gardener) are never published and their queued writes don't replay (G178, G181; [docs/edge.md](docs/edge.md)). Bundles published before this need a fresh `edge publish`.
- Memory sync follows the agent's view as it stands at each check: a note the owner hides stops its questions and corrections at once, and a reply about it answers like an unknown id (G180). `memsync approve` and `memory_check` never send a value the owner has replaced since grading (G187). A quiz answer no longer clears a memory-file card (G186). `memsync list` and the digest quote agent text on one line (G195).
- Writes: a value holding a word the writer only sees as `[withheld]` is refused as a leak, so a guess at a hidden word is never confirmed, dated or merged (G188).
- Texts: every line a text is built from is checked whole, not only proposals (G96): a dispute whose clean options join into "forward … to <address>" loses its options and points to the dashboard, and any item title that reads as instructions keeps only its kind (row 234, red team 1015b #8).
- Sign-in keeps working through an authorization-server outage for up to a day on the keys in hand; a key the server drops during the outage stays trusted until the next good fetch ([docs/oauth.md](docs/oauth.md)).
- Source text is bounded: a captured value over 200 characters is dropped as too long to be a fact, the digest clips proposal values to 120 characters and reasons to 300, and verify and source-check quotes that read as instructions are withheld ([docs/capture.md](docs/capture.md), [docs/sources-pull.md](docs/sources-pull.md)).
- Handoffs (red team 236): one alerted hold now stops a sender on handoffs and relay-hook messages alike (G189); `__proto__` and other prototype names are never agents (G190); a paused or read-only agent can't mark a handoff done (G191); NEL, other C1 controls and Unicode line separators can't break a handoff's one line (G192).
- Memory sync no longer hands an agent a value or note id that its read path withholds: questions, corrections and the change feed show `[withheld]` and `[[redacted]]` like a read does, and a correction logged with a raw value is held back. The memory-folder scan and `memsync import` no longer follow symbolic links ([docs/memory-sync.md](docs/memory-sync.md#rules-that-hold)).

### Fixed

- The test suite runs the same on every machine: test and eval runs use their own git config (a cloud container's commit signer failed 67 tests when busy), a machine missing ssh-keygen, age, ffmpeg or Chromium stops at once with one line saying what to install, and the merge gate refuses a check run with any skipped test (backlog #278). GitHub CI may still run without ffmpeg until its workflow installs it.
- A hub restart in the middle of a job no longer loses it (`test/restart-recovery.test.ts`). A source item cut off mid-extraction is extracted on the next pull instead of skipped as a duplicate. A memory correction stuck between two steps is finished at night. An ask whose phone push went out unrecorded is sent again. An agent write whose after-check was never queued is queued at night.
- `pocketbrain doctor` no longer warns that a tunnel "forwards every path" when its ingress ends in `http_status:404`, the catch-all `pocketbrain hub tunnel-config` itself prints.
- Another person's MRI, sick leave, lawyer or tribunal, insurance claim or student loan, and attributes like medicalLeave, are now forced private like other health, legal and money details (G197).
- A reader token enrolled at the sealed edge decrypts only a cell carved under the reader role: its holder's own client can no longer open the agent's private notes from the bundle. Bundles are now v2: run `pocketbrain edge publish --out <dir>` again after upgrading (G249).
- A write from an agent with hours that reaches edge replay is refused with an owner alert, as the live hours tripwire raises.
- A reader token's write queued at the sealed edge replays as the reader's, so an owner message id it cites waits in the inbox as it does at the hub; `pocketbrain edge enroll <agent> --role reader` enrolls one (G202).
- A dispute with an owner-only side (`share_with: []`) no longer shows its values to the resolver or lets it settle: the empty list counts as restricted, as everywhere else (G215). The dashboard tags such a fact "only you" (G216).
- A list fact is now hidden from an agent when any item's `share_with` leaves it out (it checked only the first item), and a write to a list fact keeps the intersection of every item's `share_with` instead of the first item's, so no item is widened (G208, G209).
- Settling a dispute no longer copies `share_with` from the first side that has one: the settled value is shared only with the agents every side's list names, and sides that share with no agent in common leave it with the owner alone (G207).
- "Only tighten" from the command line (`carve --confirm`, `consent --apply`) now compares what the agent would actually receive: dropping a slice whose `exclude_attributes` hid a fact, or dropping `money` from the left-out kinds so a bank name stops being scrubbed from a visible note, is refused as showing more (G179).
- A consent sentence about email or social media "accounts" no longer keeps money in; only an explicit money word does. The consent page says, above its Apply button, when the proposal shows the assistant more than today and when money is kept in (G183).
- `carve <new agent> --confirm` leaves money out by default, like `add` (G193).
- "Only tighten" from the command line also compares the grant itself, so `consent --apply --exclude-types none` (or `carve --confirm`) can no longer drop money from an agent while no money note is in its slice today; a dropped held-back note or attribute, or a new area, is refused too (G228).
- `carve --confirm --exclude-types none` on an existing agent writes the list it checked, never the old one (G229).
- "Only tighten" decides a slice swap on the slices' filters: from the command line, each new slice must sit inside one of the agent's current slices, so swapping to a slice that drops a tag, sensitivity or kind filter is refused even when no note it would let in exists yet (G248).
- "bank holiday" and "river bank" in a consent sentence no longer keep money in; mortgage, loans and salary count as money words again (G230).
- The `updated` date an agent is shown (meta line, read answer) no longer moves when a fact it can't see is written: a note with a hidden fact shows the newest date among its visible facts, else `created`; search age uses the same date (G222). A cell file holds that date too (it copied the raw one). Trade-off: a body edit in a note that has a hidden fact shows an older date, so `updated` can be earlier than the latest body edit and the note ranks older in search; the date also jumps when a note gains its first or loses its last hidden fact (G222, G232).
- whats_new and changes_since date a note by the newest commit that changed a fact the agent sees, so a commit that touched hidden facts alone no longer sets `at` or `by`, and changes_since no longer lists a note only hidden facts changed (G231). A commit with no fact trailer (the dashboard text editor, a pull, a hand edit) is judged by the facts that differ from its parent, and a fact that was retired still counts as a change the agent could see; the editor and the source recheck now name the facts they change. A change-feed read that fails is not remembered as "nothing changed".
- A note's search age reads only the facts the agent can see, so a hidden fact's recent date, or the `updated` its write sets, no longer moves the note's rank (G220). `updated` is the fallback only when no visible fact is dated.
- A leak refusal no longer tells the writing assistant which hidden note and fact (or canary) its value matched; only the owner's alert names it (G165).
- The first read after a write at 10k notes takes about 0.4 s instead of 2.7 s: a cell is updated in place, only the notes a change can reach are rendered again, and the read reloads only the files that changed. Its budget in `bun run perf` drops from 5 s to 500 ms ([docs/perf.md](docs/perf.md)).
- When a hidden value's disguised forms change, a cell now renders again every note that already holds `[withheld]`, so a value written next to it in another form is scrubbed too (G132).
- Access requests: a name that reads as an existing agent through letter pairs (cl as d, rn as m, vv as w), or that is an existing agent's id with a number after it (helper2, steward-1), gets a plain assistant-N id instead of a near-copy shown alone in the push; blank-looking fillers (Hangul fillers, the empty Braille cell) are dropped from the request's name and purpose, and piled-up accents are cut to two (G167).
- A secret shape in an attribute name, `share_with` or a new note's area is refused like one in a value, so no write can stop backups; agents' memory-sync answers and notes are logged redacted, so `log/memsync.jsonl` always goes in; and the drill fails when a backup leaves a `log/*.jsonl` out (G182, G185; [docs/backup.md](docs/backup.md)).
- The dashboard's "claimed to be you" warning now shows on any inbox card that cites an owner message id you never registered, not only on trial agents' cards. A write sent to the inbox because another agent owns the area, or by a conflict, used to look like an ordinary change to approve, and approving it registered the made-up id as your word (G203).
- Agent API and MCP: a non-object JSON body, non-object MCP `arguments` or a bad %-escape in the path get a 400 instead of a 500, and a mangled `rules/tokens.yaml` line is skipped.
- The relay retries a send the mail service refused instead of recording it delivered, raises a `relay_failed` alert (once a day per message and cause), and text-channel items name an outside address as "an outside address" ([docs/text-channel.md](docs/text-channel.md)).
- Memory sync never reads a fact held only as `[withheld]` or `[[redacted]]` as gone, so it no longer proposes that an agent forget it.
- `handoff list` no longer shows handoffs the owner dropped, and "keep the owner out of the loop" is held like "keep Louis out of the loop".
- Consent's money words: "mortgage" counts, and plain "accounts" or "pay" (email accounts, pay attention) no longer let money in.
- A handoff whose request check was running when the hub restarted no longer stays "checking" (unseen) forever: the next start and the night pass check it again, or hold it for you when no model is keyed.
- A texts source no longer reads the text channel's own thread: the hub's texts to the owner quote proposals and sources, so a pull could have read them back and confirmed a fact from its own echo ([docs/sources-pull.md](docs/sources-pull.md#live-discord-texts-and-granola)).
- An area added later under an existing agent's name (an `areas:` key, or a note's `area:` edited by hand) no longer hands that agent every note in it: an agent's own area holds only its capability notes and what it wrote there itself; the rest goes through its slices. `init` refuses an agent named after one of its areas (G176, [docs/add-an-agent.md](docs/add-an-agent.md)). Changed: notes you or an import wrote in an area named after an agent leave that agent's view; give it an `area:<name>` slice to keep the whole area (`pocketbrain explain <agent>` lists what dropped).
- An assistant's retract of a fact or list item the owner confirmed now goes to the owner's inbox instead of ending it (G173).
- The owner's word now wins every conflict step: an assistant's more precise date (the owner said 2026-11, an assistant writes 2026-11-05) or a later `merge: max|min` value no longer replaces an owner-confirmed value; it opens a dispute for the owner, like any other contradiction. The owner's own refinement, or the owner accepting one, applies as before (G163).
- The decision deck's auto-decide step takes a lock shared by every process on the brain, so the hub's tick and `pocketbrain deck auto` (or two copies of it) can't settle the same item at once ([docs/decision-deck.md](docs/decision-deck.md)).

- A rules edit that lands while an agent's cell is being built no longer leaves that cell marked current; the next read rebuilds it (G106).
- A release no longer needs a tag pushed from a session: GitHub refuses cloud sessions' tag pushes, so CI makes the tag `vX.Y.Z` itself when a push to `main` carries a dated, untagged version (`bun scripts/release.ts due`).
- A write commits only its own files; an inbox answer, a relayed owner message id and a replica's refused commit no longer look saved when git didn't record them ([docs/perf.md](docs/perf.md)).
- A second `pocketbrain init` (a demo or test brain) no longer moves the remembered brain that commands without `--brain` use; it says which brain they still use (G143).
- `init` makes the first assistant the owner of the one area it reads only; the other areas start with no owner, so writes there come to you until you name an owner that can read them (G144).
- A year of growth: the night pass now packs the brain's git and rotates the hub's launchd logs, an agent's write no longer stops for git's own gc, and a `.git` over its budget shows in the health probe. `scripts/perf.ts` reports a year's disk use.
- A password, PIN or door code written without `:` or `is` (`my bank password hunter2`, `PIN 4821 for the alarm`, `password - …`, `door code 4821#`, `the alarm code is 4821`, `mot de passe …`, `code de la porte 4821`) is now blanked at capture and refused on the write path; ordinary text such as `PIN the poster` or `door code is on the fridge` still passes (rows in `test/ceilings.test.ts`).
- The leak matcher shared by the relay and the write path sees through more cheap encodings: the write path no longer lower-cases before decoding base64 (G113), one malformed %-escape no longer turns URL decoding off for the whole text (G114), and HTML entities, Greek capital look-alikes and the dotless ı are folded (G115). What it still misses is listed in test/ceilings.test.ts.
- The week's "your time" no longer counts an open Map or FGA tab: the grids' 2-second polls and search-as-you-type aren't page loads, and the dashboard writes at most one owner-time line a minute.
- A dashboard POST that isn't a form, or has a malformed Referer, gets a 400 or a plain redirect instead of a 500.

### Added

- Who read what: `pocketbrain reads <agent>` and the agent page's "What it read, day by day" list the notes an agent was handed and its searches per day, with an "unusual" line when most of a day is outside its usual areas (backlog #277).
- Contradiction finder in the night pass: two notes for the same person, org or project that disagree on a fact, from different sources, become one dispute packet listing both, with the conflict order's suggestion; nothing is resolved or changed ([docs/sleep-and-explain.md](docs/sleep-and-explain.md)).
- A property test for the carve (`test/carve-property.test.ts`): random seeded brains and policies, every agent and reader token, through the live MCP tools; any carved-out value, name, id or date in an answer fails with its seed, and failing seeds are frozen as fixtures. Its first soak found G254 (a handoff can name a note its recipient can't see) and G255 (a merge's dispute packet crashes on a list against a single value), and reproduces G151 and G208.
- Frozen fixture brains for each past format (`test/fixtures/brain-formats/<n>/`): every release migrates each one to the current format and checks that it loads, that notes survive a save unchanged and that agents read it (backlog 274).
- Reconnect without piling up apps: when you let a new sign-in connection in as an agent that already has one (claude.ai and Muse register a new client on every Reconnect), it replaces the old one. The old client is refused at once and listed under "Replaced by a reconnect"; one click on the Assistants page, or `pocketbrain oauth cleanup`, deletes those apps at Auth0, so the free tenant's app cap isn't hit. `oauth bind --keep-old` keeps both, and binding a replaced client again with it undoes the replace until cleanup runs. The management app, the Gardener's machine app and coworkers' connections can't be bound to an agent, so they are never replaced or deleted ([docs/oauth.md](docs/oauth.md)).
- Where a fact came from: `pocketbrain why <id#attribute>` and a **Where from** link on each fact in the dashboard show its sources and how strong they are, earlier values, and every write on it. Assistants get a `why` tool (`GET /v1/why`) for facts in their own view, with no earlier values, no refused writes and no other assistant named ([docs/why.md](docs/why.md)).
- `pocketbrain token rotate <agent>`: a new pasted token while the old one keeps working for an overlap (24 h by default), then stops, so an assistant never breaks mid-rotation; `pocketbrain doctor` warns on a pasted token older than 90 days ([docs/add-an-agent.md](docs/add-an-agent.md#rotating-a-token)).
- `pocketbrain doctor --fix` previews the repairs doctor knows are safe (a stale git lock, `rules/gardener.yaml`, `public_url` from the tunnel's hostname, the tunnel's ingress, a backup), and `--fix --yes` runs them and checks again. Doctor now also reports a stale `.git/index.lock` ([docs/hub.md](docs/hub.md#pocketbrain-doctor---fix)).
- No hand-typed rules files for the gardener and the door: `pocketbrain gardener setup`, `pocketbrain night managed|local`, `pocketbrain hub url`, and `pocketbrain fga model` now saves its `model_id`. `pocketbrain doctor` names the command for any value still missing.

- Memory Passport 0.2: the open spec now covers handoffs (the sender learns nothing from the answer; the recipient never gets a hidden value or the sender's name), route-limited credentials such as the resolver token, sign-ins the owner hasn't approved yet, and an optional request budget (`429` with `Retry-After`, counting requests rather than content). The conformance suite has a check for each (H1 to H3, P1, P2, Q1, B1), with `--resolver` and `--waiting` credentials and a broken server per rule; the reference server and pocketBrain both pass, and discovery says `memory_passport: "0.2"` ([docs/spec/memory-passport.md](docs/spec/memory-passport.md)).
- `pocketbrain export` and `pocketbrain import`: the whole brain as a Memory Passport bundle (notes and the rules a carve reads; no tokens, logs, inbox or secrets) and back into a fresh folder with the same carve for every agent, or one agent's slice exactly as its reads answer, for another memory tool ([docs/export.md](docs/export.md)).
- Source quotes on the owner's text are weighed like values (health, school, legal and money words make the item private, and the whole line is checked for split instructions); queued texts stop being served once their items are decided; `undo --run` commits only what it reverts; quotes older proposals kept in their reasons move out of git at the next digest; the hub keeps no source sentence from checking an agent's link ([docs/sources-pull.md](docs/sources-pull.md#facts-not-copies)).
- `pocketbrain uninstall`: the plan of everything pocketBrain put on the Mac (launchd jobs, logs, the tunnel config it wrote, the menu-bar app, the keys folder), run with `--yes`; the brain and its backups stay (`--remove-brain` for the brain only), and what lives in your accounts (sign-in clients, tunnel, gardener deployments) is listed with the exact command ([docs/quickstart.md](docs/quickstart.md#leaving)).
- A French-English word map for search (`src/lexicon.ts`), off unless `PB_LEXICON=1`: a question in one language finds a note written in the other. On questions written blind by a separate writer it lifts top-5 recall from 18% to 50%, short of the 85% semantic-search gate, and loses no same-words question. The retrieval golden set gains 52 notes' worth of blind and same-words questions and measures both modes in CI.
- Retrieval is measured in CI: a synthetic French and English golden set (66 questions over 28 fictional notes, with accents, nicknames, paraphrases and carve checks) runs through `core.search` and `contextPack` on every push, against a committed baseline and the 85% held-out gate. It scores 100% on direct questions and 73% held-out, which opens gap G172 (add semantic search).
- Consent in plain words: `pocketbrain consent <agent> "what it is for"` and a "What is it for?" box on each assistant's dashboard page propose a slice from one sentence, with examples of what it would and wouldn't see. Code checks every proposal (never all, money out unless asked) and nothing changes until the owner applies it ([docs/consent.md](docs/consent.md)).
- A request budget per agent on every door: 120 requests a minute and 300 writes an hour by default (`budget:` in policy.yaml, per agent too). Past it the agent gets a 429 with Retry-After, or a tool error on MCP, and you get one alert a day. Each assistant's dashboard page shows its live counts against the budget, per token role, in red near a cap, so a loop shows before the 429 ([docs/hub.md](docs/hub.md#request-budget)).
- Handoffs: an assistant hands a task it started to another (`hand_off`, `POST /v1/handoffs`). The recipient sees it first in `whats_new` until it marks it done. Handoffs are checked like relay mail against the recipient's slice, trial agents' are held for the owner, a delivered one is checked again under the reader's token and current slice, secrecy toward the owner and a sender's later handoffs after an alerted hold are held, and `pocketbrain handoff` lists and decides held ones ([docs/handoffs.md](docs/handoffs.md)). With the relay's request check on, handoffs are read by its model too, and the browser door shows them on What changed with a Done button.
- `pocketbrain beliefs plan`: the belief radar's quiz budget, at most 10 questions per assistant a week, spent on never-asked facts first, then by standing, reads and age; `--ask` asks them ([docs/memory-sync.md](docs/memory-sync.md#quiz-budget)).
- A daily self-check in the hub's health probe: it warns before a hand fix is needed when the gardener missed its night, an assistant that used the brain has gone quiet for 3 days, `log/` grows past 500 MB or `main` has waited over 7 days for a release, and fails on under 1 GB of free disk or a hub restart loop. Warnings alert once without breaking the real-use streak; the digest carries one `Self-check:` line ([docs/real-use-bar.md](docs/real-use-bar.md#the-daily-self-check-early-warnings)).
- Silent sources: once the consent line is given, a listed source that made no proposal and re-confirmed nothing for 72 hours fails the probe's `fill` check (one alert, a Needs-you line), and the digest opens its sources section with a fill line against the weekly target ([docs/sources-pull.md](docs/sources-pull.md#silent-sources)).
- The digest's Numbers open with one Scorecard line: the latest memory exam's pass count and the latest switch-day score, each with the day it was measured.

- `pocketbrain memsync report <agent>`: a drift report of an agent's readable memory (Claude Code's CLAUDE.md and memory folder) against the brain, line by line: what contradicts it, what is stale, what the brain lacks, each with file:line and the brain's sources; contradictions and stale lines become corrections for the owner ([docs/memory-sync.md](docs/memory-sync.md#drift-report)).
- Each inbox proposal carries an evidence block the hub writes (the notes it touches, its refs, the value it replaces, and any `verify_source` verdict for that exact value), shown on the dashboard card beside Approve, with the hub's own source check and its quote; a verdict from a source that reads as instructions says so ([docs/gardener.md](docs/gardener.md)).
- An access request's name is never the new agent's label (always its id), and a hand-typed label with look-alike letters or your name inside it is refused (G70).
- Look-alike names go further: digits read as letters and l as i ("p1anner" is planner), a name holding a hub role ("gardener-bot") reads as that role, more look-alike letters fold (ı, ɪ, г, ω), and bidi and zero-width characters are dropped from a request's name and purpose (G160 to G162).
- The real-use bar counts hand fixes the hub can see without being told: an edit committed to the brain outside pocketBrain, a hand restart of the hub, the menu's Restart hub and the repair commands `hub replay`, `hub promote` and `restore`. Its line now says how many days since the last hand fix, and the dashboard's Overview has a "Real-use bar" card with the streak, that count and the restore drill. The self-check's warnings don't break the streak ([docs/real-use-bar.md](docs/real-use-bar.md#hand-fixes-the-hub-sees-by-itself)).
- The open spec's conformance suite has must-fail cases: a hidden note answers like a missing one however its address is written and when searched by id, flags only tighten (F1 to F5), and identity comes from the credential alone (I1 to I3). Eight broken servers prove each check bites, and `bun run conformance` (CI job `conformance`) runs the suite over HTTP against the reference server and pocketBrain.
- The brain carries a format number (`FORMAT` at its root). A pocketBrain that finds a brain newer than it knows stops every command with one line saying what to run, before reading or writing anything, so going back to an older release after a newer one changed the brain ends in a clean stop. An older brain is migrated after a dry run on a copy: `pocketbrain migrate` shows it, `--apply` runs it as one commit, and `start` applies it by itself ([docs/release.md](docs/release.md#brain-format)).
- `pocketbrain week` has a Fill quality section: per source, the capture cards you accepted, accepted then corrected (a changed value or "never right", not a "Still true"), and rejected, your seconds per card, and a "Turn down <source>" nudge when a source falls under 70% accepted over 5 or more cards ([docs/sources-pull.md](docs/sources-pull.md#is-the-brain-filling)).
- The act door (backlog #204): an agent with an `act` block in policy.yaml can ask to send one mail (`act`, `act_status`, `POST /v1/act`, `GET /v1/act/{id}`) to addresses the owner listed. Every mail waits for a dashboard approval bound to its exact text; texts can only reject. Fake transport only (`actions/fake/sent.jsonl`). See docs/act.md.
- The act door (backlog #204): an agent with an `act` block in policy.yaml can ask to send one mail (`act`, `act_status`, `POST /v1/act`, `GET /v1/act/{id}`) to addresses the owner listed. Every mail waits for a dashboard approval bound to its exact text; texts can only reject. Fake transport only (`actions/fake/sent.jsonl`). See docs/act.md. A text rejects or puts off a mail only by its code (G146). A mail holds only characters the owner sees on the card (tag characters, variation selectors and blank fillers are refused, G210); a local part holding a word of a value the agent can't see trips the latch (G211); a secret in `why` is refused, so the actions log stays in backups (G212).
- The decision deck: everything that needs you as swipe cards at `/deck` (Decide in the dashboard), with the evidence under each question, Later, Undo, today's count and a streak. When you don't answer, the hub lets an outside assistant's unanswered proposal expire (after 14 days), never on private, money, health or legal items, your own word, mail, captures, alerts or rules; conflicts always wait for you. Each decision is in the digest and one tap undoes it. `pocketbrain deck [auto]`, and `auto_decide` in `rules/escalation.yaml` ([docs/decision-deck.md](docs/decision-deck.md)).
- The morning swipe: each fact a source pull or capture proposed is a deck card with its source and the words it came from (keep, drop, fix, later), and `pocketbrain fill` grades the seconds you spend on them against 2 minutes a day ([docs/decision-deck.md](docs/decision-deck.md#the-morning-swipe)).
- The browser door's tab shows the pocketBrain logo, the same favicon as the dashboard, readable on dark tabs ([docs/browser-door.md](docs/browser-door.md)).
- Voice notes: an audio file in the capture drop folder, or given to `capture --voice`, becomes a voice capture of its transcript. Off until the owner sets `capture.transcribe` in `rules/models.yaml`: a local command such as whisper.cpp, or an OpenAI-compatible API with a key. The audio never enters the brain ([docs/capture.md](docs/capture.md#voice-notes)).
- `pocketbrain tend --managed` writes the gardener's Claude Managed Agents files for the owner's own Anthropic account, from their brain (name, door, timezone, windows); `--apply` runs them through `ant` with the token sent to the vault on stdin and each deployment paused as it is created ([docs/gardener.md](docs/gardener.md)).
- `tend` refuses gardener windows whose managed run would start between 01:00 and 03:00 local, where clocks change: the run would repeat in the fall and be skipped in the spring ([docs/gardener.md](docs/gardener.md)).
- A door per pilot user: `pocketbrain pilot door <name> --zone <zone>` makes a named tunnel and hostname through cloudflared; `pocketbrain door install` puts the credentials on the pilot's machine (0600), writes the agent-API-only ingress and sets `public_url` ([docs/pilot-door.md](docs/pilot-door.md)).
- Releases: `bun scripts/release.ts cut` dates the changelog, sets the version and tags `main`; a pushed tag runs CI again, makes the GitHub release and moves the `release` branch ([docs/release.md](docs/release.md)).
- The Mac hub follows releases by itself (`scripts/deploy.ts` under launchd): install, restart, health check, and back to the previous version if the hub doesn't come up healthy. The health probe alerts on a rollback or a stalled update.
- UI regression: every dashboard and browser-door page is compared with a saved snapshot in `test/ui/` on every push.
- End-to-end regression on every push (`bun run e2e`): a real hub, and one fake assistant through each door (bearer, browser, OAuth, local) reading, writing, being held, refused, paused and revoked, plus the free switch-day check.
- Belief radar: `pocketbrain beliefs` shows, per fact, what each assistant's own memory last said, graded against the brain as it reads now; `pocketbrain beliefs fix <key>` fixes one fact in every assistant at once, never with a value the owner changed since the answer was graded, and agent answers print on one line with no terminal escapes ([docs/memory-sync.md](docs/memory-sync.md)).
- A Mac menu-bar app (`macos/PocketBrainBar/`): hub up or down, day N of the real-use bar, open the dashboard, pause, set read-only or cut off an agent (resume stays on the dashboard), install or restart the hub under launchd. Its logic is `pocketbrain menubar` and `pocketbrain agent pause|read-only|revoke <agent>`, which only tightens a switch ([docs/menubar.md](docs/menubar.md)).
- The menu-bar app's first-run window: name, folder and an optional notes file make a brain, install the hub and show what to paste into the first assistant, with no terminal (`pocketbrain menubar setup`).
- An assistant waiting to be approved can file an access request itself (`request_access`: name, purpose, slices it would like). The dashboard shows it with a prefilled review and Approve as trial ([docs/add-an-agent.md](docs/add-an-agent.md)).

### Changed

- A stale ref lock (`refs/heads/<branch>.lock`, `HEAD.lock`, `packed-refs.lock`) left by a killed git command is cleared before a commit, like `index.lock`, so writes don't stop with "cannot lock ref". `pocketbrain doctor` warns when the tunnel's cloudflared config forwards an older set of paths than `pocketbrain hub tunnel-config` (such as no `/b`) ([docs/hub.md](docs/hub.md)).
- A write that puts back a value the brain replaced, citing only agents' own memory, is refused (`replaced_value`) instead of opening a dispute; cite a checkable source to get past it ([docs/memory-sync.md](docs/memory-sync.md)).
- `carve <agent> --confirm` only shrinks an existing agent's slice, and writes one owner commit. A new agent from it follows `add`'s rules (trial, never `all`). Widening an agent happens on the dashboard, behind your login ([docs/add-an-agent.md](docs/add-an-agent.md)).
- The hub now lets an outside assistant's proposal you leave unanswered expire after 14 days, on by default, including on a hub you upgrade. Conflicts are never decided for you. The clock starts no earlier than the first time the hub sees the card, so nothing old is decided at once. It happens only inside `pocketbrain start`, never on a proposal you answered in the same tick. Each decision is in the digest with Undo. To keep every decision yours, set `auto_decide: { off: true }` (or just `auto_decide: off`) in `rules/escalation.yaml` ([docs/decision-deck.md](docs/decision-deck.md)).

- Dashboard and browser door pass WCAG AA contrast and labelling checks: darker muted text, status and link colours, labels on every field, the browser door follows dark mode and has a main landmark. The dashboard calls agents "assistants" everywhere (the Agents tab is now Assistants). Every page is checked in a real browser, light and dark, with screenshot baselines ([docs/ui-quality.md](docs/ui-quality.md)).
- `pocketbrain fill`: is the brain filling? Per source, capture proposals kept and dropped, pull re-confirmations and owner minutes, against 50 facts a week, 85% kept, 2 minutes a day ([docs/sources-pull.md](docs/sources-pull.md)).
- A waiting sign-in on the OAuth door now gets a waiting session (`initialize` and `request_access` only) instead of a 403 on every call. It still reads nothing.
- Access requests, after a red team (G69 to G73, [docs/add-an-agent.md](docs/add-an-agent.md)): `request_access` gives one fixed answer, so it can't be used to guess slice, agent or owner names. A requested name that reads as the owner or another agent never becomes a label (the agent id is used, and Approve refuses such a label), and the card marks the name and purpose as the assistant's own words. The ask-to-see phone push names the agent by id, with its label beside it. The card warns, with no one-click review, when a request looks like an agent you paused or set read-only. Only `area:` slices and slices marked `requestable: true` are pre-checked. `pocketbrain add` and Approve refuse the reserved names `hub`, `relay` and `gardener`, as the docs said.
- Request bodies are capped as they stream, so a chunked body can't get past a route's limit, and the hub refuses any body over 1 MB (or the owner's raised log or capture limit) before reading it.
- Texts to the owner name the source of a pulled fact and quote the words it came from, so keep or drop takes one look ([docs/text-channel.md](docs/text-channel.md)).

## [0.1.0] - unreleased

The first version, used daily by one owner with hosted assistants connected over MCP. Not on npm yet: install with `git clone` and `bun link` (see [docs/quickstart.md](docs/quickstart.md)).

### The brain

- Plain Markdown notes with YAML facts in a git repo the owner keeps. Each fact carries its source, `as_of` and `review_after`; freshness (`fresh`, `due`, `stale`, `disputed`) is computed when a view is built and handed to agents with every fact ([docs/history/memory-shape.md](docs/history/memory-shape.md)).
- `pocketbrain init` starts a brain from nothing: a short interview, a plain-text seed, or a mail and calendar export ([docs/quickstart.md](docs/quickstart.md)). Notion import with text repairs.
- `rules/` holds the owner's policy: agents, slices, sensitivity, checks. Only the owner edits it, and any other change to it is flagged.

### Who sees what

- Carving: each agent gets a slice compiled from policy into its own cell. A withheld value inside a visible sentence stays withheld (`[withheld]`, `[[redacted]]`), and `explain <agent> [topic]` says why any fact is in or out.
- Per-agent revocable tokens, a pause switch, and an OAuth door for assistants that can only sign in (any standards-compliant authorization server; [docs/oauth.md](docs/oauth.md)).
- `pocketbrain add <agent> --slices …` onboards a new agent as a trial with money out; the dashboard can approve a new sign-in as a new agent ([docs/add-an-agent.md](docs/add-an-agent.md)).
- OpenFGA as an optional second lock on slices ([docs/fga.md](docs/fga.md)).
- Agent-to-agent mail goes through a relay that holds anything outside the recipient's slice.

### Agents' door

- One hub serving MCP (`/mcp`) and a JSON API (`/v1`, with OpenAPI), with an orientation generated per agent from its carve.
- Tools: `context_pack`, `search` (BM25 over the agent's own view), `read`, `remember`, `retire`, `capture`, `log_session`, `whats_new`, `memory_check`.
- The write path: schema, secret, injection and protected-path checks that can't be switched off, a leak tripwire, entity resolution, a conflict resolver that only takes a stronger or newer source, and an inbox for anything outside an agent's own area.
- Agent memory sync: readable agent memories are scanned and other agents quizzed; corrections are signed, approved by the owner and verified ([docs/memory-sync.md](docs/memory-sync.md)).

### Keeping it true

- Nightly upkeep and a sleep pass that forgets unused facts (undoable), consolidates agent journals and writes a morning note ([docs/sleep-and-explain.md](docs/sleep-and-explain.md)).
- A gardener role for a managed agent that reads everything, only proposes, works in set hours, and has a daily proposal cap ([docs/gardener.md](docs/gardener.md)).
- Checks after agent writes: a quick model conflict check and an optional second-opinion classifier ([docs/aftercheck.md](docs/aftercheck.md)).
- Source pulls: the hub reads the owner's own sources (mail, calendar, Discord, texts, Granola, Drive) on an allowlist in `rules/sources.yaml`, keeps facts with versioned refs and never stores the pulled text; a moved or deleted source turns its facts due ([docs/sources-pull.md](docs/sources-pull.md)). Live readers for Gmail, Calendar, Drive (listed folders only), Discord, texts and Granola are read-only, and nothing is read live without a `consent:` line in that file.
- Bring-your-own model for model-judged steps, with monthly and per-step spend caps; reads and writes are never metered ([docs/usage.md](docs/usage.md)).

### The owner

- A loopback-only dashboard: Needs you, who sees what, history, in-place edits, Ask, agents, spend.
- A daily digest, a text channel (iMessage, SMS or a relaying agent) with one-word replies, and quick capture by mail or a phone drop folder ([docs/text-channel.md](docs/text-channel.md), [docs/capture.md](docs/capture.md)).
- The first-week and real-use measures: `reexplain`, `minutes`, `week`, `fix`, `bar`, `task` ([docs/real-use-bar.md](docs/real-use-bar.md)).

### Running it

- `pocketbrain start` runs the server, dashboard, text channel, relay, nightly jobs and digest in one process, with launchd files for a Mac; a health probe checks the public door and the hub's own jobs.
- One hub and many replicas, with signed commits and a commit gate ([docs/hub.md](docs/hub.md)).
- Encrypted backups with rotation, restore onto a clean machine, and `pocketbrain drill` to prove it ([docs/backup.md](docs/backup.md)).
- `pocketbrain doctor` and `pocketbrain handover --to <dir>` to give the whole brain to a person.

### Known limits

- Install is from source; the npm package is prepared but not published.
- A hosted assistant keeps whatever it was shown in a session; pocketBrain decides what crosses the line, and can't reach across it afterwards.
- The hub runs on one machine the owner keeps on; agents can't reach the brain while it's off.
